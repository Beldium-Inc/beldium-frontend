I will fix the infinite loading bug in the onboarding page.

### **The Issue**
In `src/app/onboarding/page.tsx`, when `profile` is null (which is true for new users starting onboarding), the code sets step 1 and then immediately returns from the `init` function.
```typescript
if (!profile) {
  setStep(1);
  return; // <--- This prevents setBooting(false) from running
}
```
Because `setBooting(false)` is located at the end of the function, it never executes, leaving `booting` as `true` forever. The UI then stuck on the `<Spin />` component.

### **The Fix**
I will remove the `return` statement so execution continues to `setBooting(false)`.

### **Plan**
1.  **Modify `src/app/onboarding/page.tsx`**:
    -   Locate the `if (!profile)` block inside `useEffect`.
    -   Remove the `return` statement.
    -   Alternatively, I could add `setBooting(false)` before the return, but removing the return allows the logic to flow naturally to the end of the function where `setBooting(false)` is already called. Since the `else` block handles the `profile` logic, removing the `return` is safe as long as we use an `else` for the profile processing.
    -   Looking at the code structure:
        ```typescript
        if (!profile) {
            setStep(1);
            return;
        }
        // ... profile processing logic ...
        ```
        The profile processing logic assumes `profile` exists. If I remove `return`, the code will crash on `profile.miner_profile_onboarding_step` if I don't wrap the subsequent code in an `else` block.
    -   **Refined Fix**: I will wrap the profile processing logic in an `else` block or simply call `setBooting(false)` before the return. Calling it before return is the smallest change.

    ```typescript
    if (!profile) {
        setStep(1);
        setBooting(false); // Add this
        return;
    }
    ```
