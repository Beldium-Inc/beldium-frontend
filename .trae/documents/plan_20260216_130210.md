I understand the requirement now. We need a "session-like" behavior for the `hasRegistered` override.

1.  **Default Behavior**: `hasRegistered: true` -> Redirect to Login.
2.  **Override**: User clicks "Register" -> Allow access to `/register`.
3.  **Persistence**: If user leaves and comes back -> Revert to Default Behavior (Redirect to Login).

To achieve this, we shouldn't simply `removeItem("hasRegistered")` because that permanently clears the flag. Instead, we should set a **temporary flag** (in `sessionStorage`) that indicates "I am explicitly allowing registration right now".

### **Revised Plan**
1.  **Modify `src/features/login/Login.tsx`**:
    -   On "Register" click:
        -   Set `sessionStorage.setItem("allowRegistration", "true")`.
        -   `router.push("/register")`.

2.  **Modify `src/app/register/page.tsx`**:
    -   Update the route guard logic:
        ```typescript
        const hasRegistered = localStorage.getItem("hasRegistered") === "true";
        const allowRegistration = sessionStorage.getItem("allowRegistration") === "true";

        if (hasRegistered && !allowRegistration) {
            router.replace("/login");
        }
        ```
    -   This way, if the user closes the tab (clearing `sessionStorage`) and comes back, `allowRegistration` will be gone, and `hasRegistered` will force them back to Login.

3.  **Cleanup**:
    -   We should probably clear `allowRegistration` once the user successfully logs in or completes the flow, but `sessionStorage` naturally handles the "leave website and come back" scenario.

### **Files to Change**
-   `src/features/login/Login.tsx` (Set the temporary flag)
-   `src/app/register/page.tsx` (Check the temporary flag)
